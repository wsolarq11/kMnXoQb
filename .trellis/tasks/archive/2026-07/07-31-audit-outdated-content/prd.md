# 审查过时与不正确内容

## Goal

全面审查项目中的"过时"（outdated）与"不正确"（incorrect）内容，输出问题清单报告。**只报告，不修改**（用户决策）。

## Requirements

审查范围（用户确认：全部）：

1. **文档与代码一致性**：根 CLAUDE.md、README（如有）、docs/（如有）、.trellis/spec/ 中与实际代码结构、命令、行为不一致的描述。
2. **代码注释过时**：注释中引用已删除/重命名的 API、旧版本行为、已失效的修复说明。
3. **依赖过时**：.csproj 包版本、TargetFramework 是否有可升级的过时版本（对照 .NET 10 LTS / Windows App SDK 稳定版）。
4. **遗留引用**：代码/文档中对已归档代码库（Flutter/Rust/egui）或旧功能的残留引用。
5. **spec 索引过时**：.trellis/spec/ 索引中与当前 WinUI 3 + C# 项目无关的条目（如 cmake-build、cpp-core、slint-ui）。
6. **未提交改动**：config/settings.json 当前有未提交修改（git status 显示 M），审查其内容是否正常。

## 审查方法

- 只读操作，不改动任何文件。
- 文档声明与代码实现逐项对照（路径、命令、行为、版本号）。
- 报告格式：按类别列出问题，每条含 文件路径:行号、问题描述、建议处理（供用户后续决策）。

## Acceptance Criteria

- [ ] 输出结构化问题清单（类别 + 文件:行号 + 描述 + 建议）。
- [ ] 清单覆盖全部 6 类审查范围。
- [ ] 未修改任何文件（除 .trellis 任务目录本身）。
- [ ] 对无法确认的事项明确标注"待确认"，不猜测。

## Out of Scope

- 任何代码/文档的修改（用户决策：只报告）。
- 新功能设计与实现。
