# C# 主线（launchpad/）退役条件决策

> 决策文档 · R4 W4 · 2026-08-03 · 本任务只定义条件与步骤，不执行归档
> 依赖：R4 W1 人工场景走查、R4 W3 干净环境安装实测

## 背景

双栈并行（C# 主线 `launchpad/` + 新栈 `launchpad-tauri/`，见 CLAUDE.md「技术栈状态」节）带来双倍维护成本：两套构建/测试/发布流水线须同时保持绿。且 C# 主线的行为断言是迁移对齐的契约——两栈各自演进会导致契约漂移、回归检测失真。本决策把「C# 主线保持可回滚」的承诺显式化为可验证的冻结条件与归档步骤；条件满足前维持双栈现状。

## 触发条件（全部满足才触发冻结）

| # | 条件 | 判定方式 |
|---|---|---|
| a | W1 人工走查全部 14 场景 PASS | `.trellis/tasks/08-03-r4-w1-walkthrough/walkthrough.md` 场景清单无 FAIL 项；FAIL 项须已修复并复测 PASS |
| b | W3 安装实测矩阵全部 PASS | `.trellis/tasks/08-03-r4-w3-install-validation/install-form-validation.md` 无 FAIL/待办项；含 MSI 安装与启动（步骤 1/2）、升级/覆盖（步骤 4）、卸载残留检查（步骤 5） |
| c | 稳定期 2 周无回归 | 自 a、b 全部通过之日（含）起算 14 天；期间 ci.yml 与 ci-tauri.yml 在 GitHub Actions 无失败 run，且无 P1 缺陷报告 |

## 归档步骤（条件满足后按序执行）

1. 冻结 C# 主线：当前仓库 C# 与新栈同处 `main`（无独立 `launchpad/winui3-mainline` 分支），等价标记为在 C# 主线最后一次变更的提交上打标签：

   ```bash
   git tag -a freeze/winui3-<日期> -m "C# 主线冻结（迁移对齐契约基准）"   # <日期> 如 2026-08-17（稳定期满后）
   ```

   若届时存在独立 C# 分支，则改用 `git branch -m launchpad/winui3-mainline freeze/winui3-<日期>`。
2. 更新 CLAUDE.md「技术栈状态」节：主导栈声明为 launchpad-tauri；C# 主线状态改为「已冻结（迁移对齐契约的历史基准）」，附冻结标签名。
3. 更新 README.md：C# 主线相关内容移除或标注为历史版本（指向冻结标签）。
4. 此后 C# 侧变更仅允许 security 级修复，且须先新建决策文档说明理由、影响面与回归验证方式。

## 归档后 C# 主线的处置

- 选项 A：保留于仓库（建议）。其测试契约（Core.Tests 117 例含 ArchUnitNET + Verify 快照，IntegrationTests 17 例）是迁移对齐的基准，删除将失去行为对照物。
- 选项 B：移入 `archive/`（如 `archive/2026-08/launchpad-winui3/`）。仓库根整洁，但契约对照需跨目录、易被忽略。
- 取舍：契约价值高于目录整洁，建议选 A；若未来新栈将契约测试并入自身 CI 而完全自证，再评估迁移至 B。

## 不触发的情况（回滚评估）

若 W1/W3 发现致命缺陷且无法在合理周期内修复：暂停冻结，评估回滚到 C# 主线。触发点：新栈无法满足 W1 核心场景（1-5：新建/编辑/删除/搜索/批量启动）或 W3 安装形态不可用。判定：缺陷记录严重度为致命且无可行修复方案时，由用户决策回滚——冻结条件作废，本决策失效并需重新决议。
