# 评估报告：C# → Rust/TS 再迁移方案（修订版）

- 日期：2026-08-01（v1 2026-08-01 初版；本版为约束修订后的 v2）
- 任务：08-01-migration-eval-rust-ts（`prd.md` / `design.md` 定义范围与评估框架）
- 基准：当前 `launchpad/src/`（C#/WinUI 3）全部功能，行为对齐以 `tests/` 断言为准

---

## 1. 结论摘要（TL;DR）

**推荐：Rust 核心 + TypeScript 前端（Tauri v2.11 + React），即路线 R3。** 依据用户 2026-08-01 约束修订：产物形态放宽为"便携 zip 解压即用 + 接受 WebView2 依赖，同时接受 MSI 安装器 + Portable.zip"（即 [cc-switch](https://github.com/farion1231/cc-switch) 的分发模式）；配置位置双轨（便携 zip → exe 旁 `config/`，MSI → 用户数据目录 `%APPDATA%`）。

**R3 成立的理由：**
1. **同类产品实证**：cc-switch（管理 7 类 AI CLI 配置切换）正是 Tauri 2 + React + MSI/Portable 双产物，v3.19.1 活跃维护——本产品形态与其同构，风险已被市场验证。
2. **Web UI 开发效率**：卡片列表/搜索/多选/对话框/主题/语言热切换用 HTML/CSS/React 实现，UI 能力显著强于 egui；中文 IME 由 WebView2（Chromium）系统级输入法承担，**无 egui 的 IME 专项风险**。
3. **lucide 约束天然满足**：React 侧用官方 `lucide-react` 组件库。
4. **领域逻辑 1:1 移植**：全部纯决策（LaunchPlanner/DangerousFlag/ItemValidator/WindowPosition/Item 集合函数）进 Rust 核心层，现有 15+ 测试文件断言可直接映射为 `cargo test` + insta 快照。
5. **配置字节兼容**：Rust serde snake_case 与 C# 输出 1:1。

**R1（纯 Rust + egui 0.35）保留为备选**：零依赖单 exe 是便携约束的上位形态，适合"WebView2 不可用"或"双轨配置不可接受"的失败回退。切换条件见第 7 节。

**排除：** Slint（许可证 + IME 无保证）、Deno desktop（experimental + 产物形态差 + Windows 故障率高）、Bun（无官方 GUI 通道）。

## 5. 决策点回答（design.md D1–D5 修订）

- **D1（TS 路线分发形态）**：修订后成立——Tauri v2 原生产出 MSI（WiX）+ Portable zip（cc-switch 实证，v3.19.1 双资产发布），WebView2 依赖被接受。Deno desktop 仍不满足（产物目录/自解压包，experimental）。
- **D2（中文 IME）**：R3 无 egui 式 IME 风险——WebView2 使用系统输入法（Chromium），中文输入开箱即用；阶段 0 仍安排实测（中文候选/组词/多行）作为验证门，但预期无阻塞。
- **D3（exe 旁配置）**：修订为双轨——便携 zip 用 Rust 侧 `current_exe()` 向上搜索含 `config/` 的祖先（与 C# `ResolveConfigDir` 同逻辑，保持字节兼容与可移动性）；MSI 安装版写 Tauri `appDataDir()`（%APPDATA%\…，cc-switch 同款）。两套路径解析需各自测试（新增 ConfigStoreTests 双轨用例）。
- **D4（旧 POC 复用差距）**：不变（见 `poc-gap.md`）——12 项缺口 + 2 个必须按 C# 修复的启动 bug；R3 路线的 Rust 核心同样按 C# 测试断言直译，不搬 POC 代码。
- **D5（是否维持现状）**：不维持。约束修订后 R3 以 cc-switch 为先例达成全部约束，且领域层测试断言 1:1 可移植；维持现状意味着继续承受 WinUI 3 的发布复杂度与功能演进约束。

## 7. 风险清单与规避（修订）

| # | 风险 | 等级 | 规避 |
|---|---|---|---|
| 1 | WebView2 依赖（Win10 LTSC 2021 不预装） | 中（已接受） | 启动时检测 WebView2 Runtime，缺失时提示安装指引（Evergreen 在线 / offlineInstaller +127MB）；发布文档注明前置条件；离线环境评估 fixedRuntime 或回退 R1 |
| 2 | 双轨配置路径复杂度 | 中 | 路径解析收敛为单一解析器（输入：安装形态标记），双轨各配 ConfigStoreTests 用例；便携形态是主场景，MSI 形态对齐 cc-switch 模式 |
| 3 | 前端-核心边界漂移（逻辑进前端） | 中 | 纯决策一律进 Rust 核心（commands 返回），前端只做状态与渲染；架构测试等价物：Rust 侧单测 + 前端 mock commands 测试 |
| 4 | 探测等阻塞操作卡 UI | 低 | Tauri commands 用 async/线程；spawn 本身非阻塞 |
| 5 | Tauri 版本演进 | 低 | 锁版本（Cargo.lock + package-lock 入库），升级走专项任务 |
| 6 | POC 复用引入旧 bug | 高 | Rust 核心按 C# 测试断言直译，不搬 POC 代码（cmd/pwsh 分支修复版） |
| 7 | MSI 场景 exe 旁不可写（若误用 Program Files） | 低 | 采用 per-user WiX（cc-switch 同款 per-user-main.wxs），安装到 %LOCALAPPDATA%\Programs，可写；文档注明 |
| 8 | R1 回退的 IME 风险（若启用备选） | 低 | R1 阶段 0 已有 IME 实测门（egui 0.34+ 修复 + 专项验收用例） |

## 8. 架构模式参考（cc-switch 成为同构先例 + CodexSwitch 对照）

### 8.1 cc-switch（farion1231/cc-switch，v3.19.1 2026-07-31）—— 首选路线同构先例

**形态完全同构**：Tauri 2 + React/TS + Vite/Tailwind，Windows 发布 MSI（WiX per-user）+ Portable.zip，WebView2 依赖，配置写用户数据目录（便携版可配置 exe 旁）。

| 模式 | cc-switch 实现 | 本产品 R3 采纳方式 |
|---|---|---|
| 每工具一个配置适配器 | codex_config.rs / claude_desktop_config.rs / gemini_config.rs / grok_config.rs / opencode_config.rs / openclaw_config.rs / hermes_config.rs | launchpad 无"接管配置"需求（只启动）；启动差异（wt/pwsh/cmd 参数规则）在 LaunchPlanner 中已是适配器等价物。**P2 扩展**：若未来管理各 AI CLI 配置，直接照此模式 |
| 可逆接管 + 所有权标记 | `PROXY_MANAGED` 占位符 + 备份恢复 + history migration | 不采纳（不接管外部配置）；.bak 备份 + 自动恢复语义保留 |
| 原子写 | config 模块 atomic_write（临时文件 + rename） | **采纳**：R3 的 ConfigStore 用 atomic_write + 保留 .bak 备份双保险（快照断言为准） |
| 集中状态 | AppState（Arc\<Database\> + services）注入 commands | 同构：Rust 侧 AppState 持有 store/spawner/检测器，commands 注入 |
| SQLite 状态库 | database/ + codex_state_db.rs | 不采纳（配置即文件，无状态库需求） |
| 前端分层 | config/（presets）+ lib/（API/错误/日志）+ components/ + i18n/ + hooks/ | 采纳：React 分层照此，但 provider presets 不适用（launchpad 无 provider 概念） |
| 双层测试 | vitest（前端）+ Rust 集成测试 | 采纳：vitest 组件测试 + cargo test 领域/契约 |
| 自动更新 | Tauri updater + MSI | P2（本产品未要求；Tauri 生态预留） |

### 8.2 CodexSwitch（AIDotNet/CodexSwitch，.NET 10 + Avalonia + Native AOT）—— 对照参考

| 模式 | 采纳情况 |
|---|---|
| 协议适配器（IProviderProtocolAdapter） | P2 参考（与 launchpad 终端适配同构） |
| 可逆托管配置（ManagedFileBackup） | 与 .bak 语义一致，采纳其"恢复后字节一致"显式测试用例 |
| Native AOT 单文件 | 对照信息：.NET 侧可行（Avalonia+AOT），但语言限制内不适用；不改变决策 |
| 集中协调器 ViewModel | **不采纳**（launchpad 纯决策 + 薄壳原则是可测性基石） |
| 配置三层分离（AppConfig/ConfigurationStore/AppPaths） | 采纳：R3 的路径解析收敛为单一解析器（双轨输入），与 AppPaths 同构 |

### 8.3 对"维持现状"的对照

cc-switch 证明"Tauri 2 + MSI/Portable 双产物 + WebView2"是同类产品的成熟生产形态（v3.x 长期活跃）；CodexSwitch 证明"单文件"在 .NET 侧需 Avalonia+AOT（WinUI 3 不行）。两条实证均支持：**在修订约束下，R3 是低风险高对齐的选择，维持现状无优势。**
