## 2. 总体架构（分层与依赖方向）

```
┌─────────────────────────────────────────────────────┐
│ React 前端（薄壳：渲染 + 交互 + 状态）                  │
│  components / hooks / i18n / lucide-react / zustand  │
└──────────────────────┬──────────────────────────────┘
                       │ Tauri invoke（异步命令调用）
┌──────────────────────▼──────────────────────────────┐
│ Commands 层（薄壳：参数校验 → 调核心 → 错误序列化）      │
│  items / launch / settings / dialogs                 │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────▼──────────────────────────────┐
│ 核心层（纯函数，无 Tauri/std::fs/进程依赖）             │
│  models / planner / danger / validator / window_pos   │
│  items / launch / i18n / errors                       │
└──────┬──────────────────────┬───────────────────────┘
       │                      │
┌──────▼──────────┐  ┌────────▼───────────────────────┐
│ 配置层            │  │ 基础设施层                       │
│ paths（双轨解析）  │  │ spawner（argv 零 shell）         │
│ store（读写/备份） │  │ terminal（探测缓存）             │
│                  │  │ window（窗口状态事件）            │
└─────────────────┘  └────────────────────────────────┘
```

**依赖纪律**（镜像 C# 版 Clean Architecture，由模块可见性强制）：
1. 依赖箭头永远向下：UI → Commands → 核心 ← 配置/基础设施。
2. 核心层**零外部依赖**（纯 Rust std + serde），任何 I/O 经参数注入（函数参数传 store/spawner）。
3. Commands 层不写业务逻辑，只做编配。
4. 前端不持有业务决策（危险检测、确认策略、id 生成全部在核心），前端只渲染结果。

## 4. 核心层设计（纯函数，行为 1:1 对齐 C#）

### 4.1 数据模型（serde）

```rust
#[derive(Serialize, Deserialize, Clone)]
#[serde(rename_all = "snake_case")]
pub struct LaunchItem {
    pub name: String,
    pub directory: String,
    pub command: String,
    #[serde(default = "default_true")] pub confirm: bool,
    pub id: String,
    #[serde(default)] pub selected: bool,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub terminal: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub tag: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub group: Option<String>,
}
```

- 未知字段：`#[serde(flatten)] extra: HashMap<String, Value>` 仅 AppSettings 保留（对齐 C# JsonExtensionData），LaunchItem 忽略（与 C# 一致）。
- 序列化：`serde_json::to_string_pretty` + 字段声明顺序 = C# 输出顺序；`JsonRoundTripTests` 快照为字节兼容验收。

### 4.2 LaunchPlanner（关键行为，C# 修复版为准）

```rust
pub fn plan_windows(item: &LaunchItem, wt_available: bool, pwsh_available: bool) -> LaunchPlan
```

- wt：`["new-tab", "-d", dir, terminal, "-NoExit", "-Command", cmd]`
- pwsh：`["-NoExit", "-Command", &format!("cd '{}'; {}", escape_pwsh_quotes(dir), cmd)]`
- cmd：`["/k", cmd]` + `current_dir(dir)`（**禁止** POC 的 `cd /d "..."` 前缀，cmd /k 引号陷阱）
- `escape_pwsh_quotes`：`'` → `''`（单引号翻倍）

### 4.3 错误模型

```rust
pub enum AppError {
    WorkingDirectoryMissing(String),  // 267/3 且目录确实不存在
    ProcessNotFound(String),          // 2
    AccessDenied(String),             // 5
    ConfigParse { path: String, detail: String },
    StoreWrite { detail: String },
    Unknown(String),
}
```

- Commands 层把 AppError 序列化为 `{ kind, message }` 下发，前端映射到状态栏文案键（保持 C# 的"错误描述英文内部诊断"策略）。
- 预期失败走 Result；panic 仅用于编程错误（对齐 C#"异常仅用于编程错误"）。

## 5. 配置层设计（双轨路径 + 可逆写入）

### 5.1 双轨路径解析（单一解析器）

```rust
pub enum InstallForm { Portable, Installed }
pub struct ConfigPaths { pub dir: PathBuf }

pub fn resolve(install_form: InstallForm) -> ConfigPaths {
    match install_form {
        // 便携：current_exe() 向上搜索含 config/ 的祖先（C# ResolveConfigDir 同逻辑）
        InstallForm::Portable => ResolveConfigDir::upward_search(),
        // MSI：appDataDir（Tauri path API），形如 %APPDATA%\<vendor>\<app>\config
        InstallForm::Installed => app_data_dir().join("config"),
    }
}
```

- 形态判定：MSI 安装版写入一个安装标记（如 `%APPDATA%\<app>\install.form`）；便携版无标记 → Portable 默认。判定收敛在单一函数，两分支各配测试。
- 便携版保持可移动性：目录整体搬移后 exe 旁 config/ 仍被找到。

### 5.2 ConfigStore（atomic_write + 备份双保险）

```
写流程：临时文件写入（同目录 .tmp）→ rename 原子替换
        + 写前将现 config.json 复制为 config.json.bak（保留 C# 语义）
读流程：config.json 损坏 → 从 .bak 恢复（LastRecoveryNote 状态栏提示）→ 双坏才报 ConfigParse
```

- 采纳 cc-switch 原子写（防半写）**叠加** C# 的 .bak 恢复（防损坏）——两种韧性机制互补，均入测试。
- 写路径：`WriteItems`（config.json）/ `WriteSettings`（settings.json），UnknownFields 写回保留。

## 6. Commands 接口契约（Tauri invoke）

| Command | 签名（Rust 侧） | 说明 |
|---|---|---|
| `list_items` | `() -> Result<Vec<LaunchItem>, AppError>` | 含恢复提示（`recovery_note: Option<LanguageKey>` 随行） |
| `create_item` | `(input: ItemInput) -> Result<LaunchItem, AppError>` | 核心 GenerateId + 校验；返回新项 |
| `update_item` | `(id: String, input: ItemInput) -> Result<LaunchItem, AppError>` | Upsert at index |
| `delete_item` | `(id: String) -> Result<(), AppError>` | |
| `move_item` | `(id: String, delta: i32) -> Result<(), AppError>` | 上移/下移 |
| `set_select` | `(id: String, target: bool) -> Result<(), AppError>` | 目标态（幂等），按 id 稳定解析 |
| `toggle_select_all` | `() -> Result<Vec<LaunchItem>, AppError>` | |
| `launch_item` | `(id: String) -> Result<LaunchOutcome, AppError>` | 核心 TryLaunch；前端先经 `needs_confirm` 决定是否弹确认框 |
| `needs_confirm` | `(id: String) -> Result<ConfirmInfo, AppError>` | 返回 `{ needs_confirm, danger_key: Option<LanguageKey> }` |
| `launch_many` | `(ids: Vec<String>) -> Result<LaunchManyResult, AppError>` | `{ succeeded, failed_indexes, history }`；成功后清空选择 |
| `get_settings` | `() -> Result<AppSettings, AppError>` | |
| `set_confirm_enabled` / `set_theme` / `set_language` | `(value) -> Result<AppSettings, AppError>` | 三态循环由核心决定（System→Dark→Light / Auto→zh-CN→en-US） |
| `get_language` | `() -> Result<ResolvedLanguage, AppError>` | 解析后的当前语言 + 键表版本（三层优先级在核心） |
| `pick_directory` | `() -> Result<Option<String>, AppError>` | Tauri dialog 插件（原生 IFileDialog） |
| `save_window_state` / `load_window_state` | `() -> Result<(), AppError>` / `-> Result<WindowState, AppError>` | close 事件触发（Restored 语义 + ClampToVisible） |

前端调用全部经 `lib/invoke.ts` 封装（类型守卫 + 错误→文案键映射），禁止散落 invoke 调用。

## 7. 前端设计（React 薄壳）

### 7.1 组件树

```
App
├── HeaderBar（搜索框 / 新建 / 全选 / 批量启动 / 主题切换 / 语言切换）
├── StatBar（项目数 / 已选数 / 最近启动）
├── ItemList（卡片网格：名称/目录/命令 + 复选框 + 危险标记 + 编辑/删除/上移/下移）
├── EmptyState / NoMatchState（按 IsEmpty/HasNoMatches 切换）
├── EditDialog（四字段 + 终端覆盖 + 确认开关 + 目录选择 + 校验错误 + 危险警告）
├── ConfirmDialog（单项：危险原因；批量：项目列表 + 逐项危险标记）
└── StatusBar（错误/恢复/成功文案，按键渲染）
```

### 7.2 状态管理（zustand）

- `useItemsStore`（items/counts/selection）、`useSettingsStore`（settings/theme/language）、`useStatusStore`（statusText）。
- 一切写操作走 invoke → 命令返回后刷新 store；**前端不本地修改列表**（保证核心单一事实源）。
- 语言切换：核心返回新语言 + 键表 → store 替换 → 组件全量重渲染（对齐 C# 热切换语义）。

### 7.3 i18n

- `LanguageKey` 枚举单一来源（core/i18n.rs）；TS 侧生成同构类型 + 中英键表（构建期同步脚本或手维护 + 键完整性测试兜底，见 D6）。
- 三层优先级（显式 > 系统语言 > 英文兜底）解析在核心（`get_language`），前端拿到"当前语言 + 键表"后纯渲染。

### 7.4 图标

- `lucide-react` 官方组件（约束"只用 lucide"）；码点/组件与 C# `LucideGlyph` 一一对应。

## 8. 架构模式清单（采纳/不采纳 + 理由）

| # | 模式 | 决策 | 理由 / 来源 |
|---|---|---|---|
| P1 | 分层 + 依赖方向（UI→Commands→Core←Infra） | **采纳** | 镜像 C# Clean Architecture；ArchUnitNET 断言的 Rust 等价物 = 模块可见性 + 单测 |
| P2 | 端口/适配器（trait + 注入） | **采纳** | spawner/store/detector 以 trait 注入，测试替身可换（对齐 C# Ports） |
| P3 | 终端适配器（wt/pwsh/cmd 规则独立） | **采纳（当前为 planner 三分支）** | P2 升级为显式 trait 集（参考 cc-switch 每工具一适配器），各分支引号规则独立测试 |
| P4 | 双轨配置单一解析器 | **采纳** | 输入形态标记 → 输出路径；两分支各配测试 |
| P5 | 原子写 + .bak 备份双保险 | **采纳** | cc-switch atomic_write（防半写）+ C# .bak（防损坏）互补 |
| P6 | 结构化错误 Result → 状态栏键 | **采纳** | 对齐 C# ErrorOr 策略；错误描述英文内部诊断 |
| P7 | 集中协调器（CodexSwitch MainWindowViewModel 式） | **不采纳** | 与纯决策 + 薄壳原则冲突；可测性优先 |
| P8 | SQLite 状态库（cc-switch） | **不采纳** | 配置即文件，无状态库需求 |
| P9 | 接管外部配置 + PROXY_MANAGED 标记（cc-switch） | **不采纳** | launchpad 不接管 AI CLI 配置（P2 扩展时再评估） |
| P10 | 自动更新（Tauri updater） | **不采纳（P2）** | 本产品未要求；Tauri 生态预留 |
| P11 | TS fs 插件读写 exe 旁文件 | **不采纳** | 文件 I/O 全收进 Rust command（current_exe 定位），规避 resourceDir 陷阱与权限 scope 复杂度 |
| P12 | 每工具一个配置适配器（cc-switch） | **P2 扩展** | 若未来管理各 AI CLI 配置，照此模式 |
| P13 | 单实例 | **采纳** | tauri-plugin-single-instance（官方）或 Rust 侧锁 |
| P14 | MSVC 静态链接 | **采纳** | `-C target-feature=+crt-static`，规避 vcruntime140 缺失 |
| P15 | 语言优先级解析在核心 | **采纳** | 可测（TranslationsTests 等价物） |

## 10. 构建与发布（双形态）

| 产物 | 生成 | 内容 |
|---|---|---|
| Portable zip | `tauri build --bundles zip`（或打包 raw exe） | raw exe（crt-static 静态链接），解压即用；运行期 exe 旁生成 `config/`；WebView2 缺失时启动检测 + 指引 |

- WebView2 分发模式（**待确认 D4**）：MSI 默认 `downloadBootstrapper`（联网装 Evergreen）；便携 zip 不带 Runtime，靠启动检测提示（联网引导 / 离线包指引 / 运维预装）。
- 体积：exe 3–10MB；MSI +（若 offlineInstaller）+127MB。
- 发布文档：WebView2 前置条件、便携/安装两种形态说明、升级路径（P2 自动更新预留）。

## 11. 关键场景数据流

**单项启动（含确认）**：
```
点击卡片 → needs_confirm(id) → 核心（confirm 全局开关 && (item.confirm || 危险)）
  → 需确认：前端 ConfirmDialog（危险原因键渲染）→ 用户确认
  → launch_item(id) → 核心 plan（终端探测缓存）→ spawner（argv + current_dir）
  → Result → 成功：PushHistory + 状态栏 StatusLaunched；失败：AppError → 状态栏（英文诊断）
```

**批量启动**：LaunchSelected → `launch_many(ids)` → 核心 RequireConfirm（危险项收集）→ 前端批量确认框 → LaunchMany 逐项 TryLaunch → `{succeeded, failed_indexes}` → PushHistoryMany（失败项不入历史）→ ClearSelection（防二次触发，对齐 C#）→ 状态栏 StatusLaunchedN / StatusLaunchedPartial。

**编辑保存**：EditDialog 校验（前端即时 + 核心权威）→ `update_item` → 核心 Upsert → store 原子写 + .bak → 状态栏 StatusUpdated；危险命令在编辑框内即时警告（danger 标记实时计算）。

**语言切换**：toggle → `set_language` → 核心三态循环 → settings 落盘 → `get_language` 返回新语言 + 键表 → store 更新 → 全量重渲染（含卡片内文案）。

**窗口状态**：`Window.close` 事件 → 若最后状态为 Restored → `save_window_state`（x/y/w/h）→ 核心 ClampToVisible 纠偏 → 落盘；启动时 `load_window_state` 恢复（-32000 离屏坐标被钳制到可见区）。
