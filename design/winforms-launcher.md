## 值得保留的经验

1. **便携的配置发现**
   - 优先在仓库根目录的 `config/config.json` 读取配置。
   - 独立副本可回退到可执行文件本地目录的 `config/config.json`。
   - UI 偏好放在同级的 `config/settings.json`，而非 AppData 或注册表。

2. **人类可读的启动契约**
   - 启动项使用稳定的 `id`、显示 `name`、`directory`、`command`、`confirm`、持久化的 `selected`。
   - `selected` 是真实状态，而非临时 UI 状态；一键启动应在重启后仍然尊重它。

3. **启动安全边界**
   - 启动前校验 `directory` 是否存在。
   - 拒绝空命令。
   - 集中处理 `wt.exe -d ... pwsh -NoExit -Command ...` 的参数引号化。
   - `dangerously*` 类命令必须经过确认。

4. **低摩擦的交互设计经验**
   - 减少界面装饰。
   - 保持卡片可读。
   - 用省略号截断过长的路径或命令，避免布局抖动。
   - 悬停时不移动卡片。
   - 批量选中状态保持可见且持久。

5. **验证习惯**
   - 根目录的 `tools/verify.ps1` 应作为无交互的原生验证门。
   - 该门应证明配置解析、危险命令加固、启动参数规则、构建可行性。

## 退役原因

- 单个 75 KB 的 `Program.cs` 混合了配置读写、启动引号化、渲染、布局、主题、编辑对话框、批量状态与持久化。
- UI 使用 WinForms/GDI 手工绘制，小幅交互改进都需要命令式重绘与布局工作。
- 围绕编译产物的反射式冒烟测试有用但间接。
- 根目录可执行文件是生成产物，将其作为主路径使源码归属不够清晰。

## 后续实现指引

后续实现应保留上述契约，但以分离的层次落地：

- 配置与启动规则放在核心层；
- UI 状态与命令放在视图模型层；
- 对话框与视图放在应用层；
- 围绕核心契约与仓库配置行为编写测试；
- 构建产物放在被忽略的 `artifacts/` 目录，不作为根目录跟踪的二进制文件。

除非当前实现无法通过同一原生验证门，且经明确回滚决策，否则不恢复 WinForms 源码或根目录的 `WT Launcher.exe`。
